# plan

무엇을 만들지(understand)를 받아 **어떻게 구현할지** 정하는 단계. 산출물은 진행 체크리스트(`task.md`)다.
코드는 작성하지 않는다 — 무엇을 어떤 순서로 할지만 정한다.

## When to Activate

- SDD 워크플로우의 **Plan 단계** — 문제 분석이 끝나 구현 순서를 짤 때
- 요구사항을 작업 단계 체크리스트(`task.md`)로 분해하고 싶을 때

## Input

- 문제 분석 (`understand.md`). 없으면 `.tracking/{슬러그}/understand.md` — 작업 모듈·영향 범위·제약.
- 요구사항 브리프 (`request.md`) — 요구사항·완료조건(AC).
- 출력 경로 (없으면 `.tracking/{슬러그}/task.md`)

## Procedure

### 1. 분석·요구사항 읽기

`understand.md`의 문제 정의·작업 모듈·제약과 `request.md`의 완료조건(AC)을 읽는다.

### 2. 계획 수립

- **접근**: 어떤 모듈을 어떤 순서로 건드릴지 전략을 한 단락으로.
- **완료 기준(DoD)**: request의 완료조건(AC)을 이번 작업 범위의 검증 가능한 기준으로 구체화. Verify의 계약.
- **작업 단계**: 순서대로 진행할 체크리스트. 각 단계는 검증 가능한 단위.
  테스트 가능한 단계는 **실패 테스트 → 구현 → 통과** 순으로 쪼갠다.
- **리스크**: 막힐 만한 지점과 대비책.

요청 범위를 넘는 단계는 넣지 않는다 — understand의 작업 모듈 밖으로 벗어나지 않는다.

### 3. 출력

이 스킬의 `template.md` 형식으로 `task.md`를 쓴다.
해당 없는 섹션은 `(없음)`으로 명시한다.

## Done

- `.tracking/{슬러그}/task.md` 가 생성됨
- 완료 기준과 작업 단계가 검증 가능한 형태로 정의됨

작성 후 사용자에게 작업 단계와 완료 기준을 보여주고, 구현을 시작할지 검토받는다.
