# manual-agent — 에이전트는 하나, 작업마다 매뉴얼

일마다 에이전트를 새로 만들면 반쯤 만든 것만 쌓인다. 에이전트는 그대로 두고 작업 영역마다 매뉴얼 하나를 준다.

## 구성 (프로젝트 안에 둔다)

| 요소          | 기본 위치                                                           | 내용                                                                     |
| ------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 매뉴얼        | 프로젝트 문서 폴더(`.claude/docs/{영역}.md` 등, 프로젝트 관례 우선) | 규칙 · 위치 · 이름 · 도구. 항목마다 상태: **정함** · **제안** · **미정** |
| 인터뷰 · 순서 | 스킬 `{영역}/SKILL.md`                                              | 매뉴얼 읽기 → 미정 항목 인터뷰 → 툴박스로 작업 → 체크리스트 → 지적 반영  |
| 툴박스        | 스킬 `templates/`, 프로젝트 `tools/` · `scripts/`                   | 새 파일을 시작하는 템플릿, 반복 명령 스크립트                            |
| 검증          | 스킬 `checklist.md`                                                 | 완료 기준 목록. 항목마다 증거(명령 · 종료 코드 · 경로)                   |

## 1. 인터뷰 → 매뉴얼

- 먼저 프로젝트에서 답할 수 있는 것은 직접 찾는다(코드 · 문서 · 설정). 찾은 것은 **정함** 또는 **제안**으로 적는다.
- 사용자만 답할 수 있는 것만 묻는다. AskUserQuestion으로 한 번에 한 질문, 선택지 2~4개, 추천을 첫 번째에.
- 답은 채팅에 두지 않고 매뉴얼에 기록한다. 지금 정할 필요가 없는 것은 **미정** 표에 선택지 · 추천과 함께 남겨, 그 항목이 필요한 작업이 올 때 묻게 한다.
- 매뉴얼 끝에 변경 이력(`- #{이슈} 한 줄`)을 둔다.

## 2. 툴박스

- 같은 파일 모양을 두 번 만들었으면 템플릿으로 뺀다. 같은 명령 조합을 두 번 쳤으면 스크립트로 뺀다.
- 템플릿은 빈칸(`{...}`)만 채우면 되게 하되, 실제 대상에 맞지 않으면 어디를 바꿀지 스킬에 적는다.
- 템플릿에 쓴 외부 API는 공식 문서나 소스로 확인한다. 기억으로 쓰지 않는다.

## 3. 검증 (가장 많이 빠뜨리는 단계)

- `checklist.md`의 항목을 증거와 함께 하나씩 확인한다. 못 채운 항목이 있으면 완료로 보고하지 않고 남은 것을 보고한다.
- 체크리스트에는 "통과했다"가 아니라 "무엇으로 확인했다"를 쓴다. 예: "테스트 통과" 대신 "일부러 깨뜨려 실패하는 것을 봤다".
- 가능하면 다른 모델(Codex 등)로 교차 검토하고, 지적을 다음 단계 규칙대로 반영한다.

## 4. 틀리면 매뉴얼을 고친다

| 지적의 종류                           | 고칠 곳        |
| ------------------------------------- | -------------- |
| 규칙 · 위치 · 이름 · 도구 선택이 틀림 | 매뉴얼         |
| 순서를 빠뜨림                         | `SKILL.md`     |
| 파일 모양이 틀림                      | `templates/`   |
| 확인을 빠뜨림                         | `checklist.md` |

- 결과물과 같은 커밋 · PR에서 고치고 변경 이력에 남긴다.
- 같은 지적이 세 번째면 훅이나 검사 스크립트로 막는다.

## 새 영역을 시작할 때

1. 반복될 작업인지 확인한다. 한 번뿐이면 매뉴얼을 만들지 않는다.
2. 위 구성의 네 파일을 만든다. 처음엔 짧게, 프로젝트에서 찾은 사실과 미정 표부터.
3. 프로젝트 규칙 색인(`CLAUDE.md` 등)에 매뉴얼과 스킬을 한 줄로 연결한다.
4. 첫 실제 작업에서 인터뷰 · 체크리스트를 써 보고 빠진 것을 매뉴얼에 반영한다.

예: UI 테스트 영역 — 매뉴얼 `.claude/docs/ui-testing.md`, 스킬 `.claude/skills/ui-test/`(`SKILL.md` · `checklist.md` · `templates/`).
