# understand

요구사항을 코드베이스 맥락에서 분석해 **문제를 정의**하는 단계.
바로 구현하지 않는다 — 무엇을 어디서 바꿔야 하고 어디에 영향이 가는지를 밝힌다.

## When to Activate

- SDD 워크플로우의 **Understand 단계** — `request.md`가 준비되어 문제·영향 범위를 분석할 때
- 요구사항을 코드베이스 맥락에서 분석해 작업 모듈·임팩트를 정리하고 싶을 때

## Input

- 요구사항 브리프 (`request.md`). 경로가 없으면 `.tracking/{슬러그}/request.md`.
- 출력 경로 (없으면 같은 폴더의 `understand.md`)

## Procedure

### 1. 브리프 읽기

`request.md`의 요구사항·완료조건·디자인을 읽는다.

### 2. 코드베이스 탐색

요구사항과 관련된 모듈·파일을 찾는다. 범위가 넓으면 **Explore 에이전트**(Agent 툴,
`subagent_type: "Explore"`)로 탐색해 관련 위치를 모은 뒤 본 컨텍스트에서 종합한다.
(메인 컨텍스트 보호)

에이전트에 넘기는 과제는 이 스킬의 `prompt.md`를 사용한다 —
`{requirements}` 자리에 `request.md`의 요구사항·완료조건 요약을 채워 전달한다.

작은 변경이면 에이전트 없이 직접 탐색해도 된다.

### 3. 문제 정의

요구사항을 코드 맥락에서 한 단계 구체화한다 — 무엇이 왜 문제이고, 무엇이 해결되어야 하는가.

### 4. 작업 모듈 · 영향 범위

- **작업 모듈**: 직접 변경할 모듈.
- **영향 범위(Impact)**: 의존 방향상 영향받는 모듈. Clean Architecture 레이어·의존 규칙으로 판단한다.

### 5. 문서 작성

이 스킬의 `template.md` 형식을 따른다.
해당 없는 섹션은 `(없음)`으로 명시한다.

## Done

- 출력 파일이 생성됨
- 문제 정의 · 작업 모듈 · 영향 범위가 정리됨

작성 후 사용자에게 요약을 보여준다. 이때 세운 **가정**과 **미해결 질문**을 함께 짚어준다 —
막아서 묻지 말고, 사람이 검토 단계에서 판단하도록 드러내기만 한다.
