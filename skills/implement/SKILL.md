# implement

`task.md`의 작업 단계를 순서대로 구현하는 **오케스트레이터**.
직접 코드를 다 짜기보다, 각 단계의 성격에 맞는 방법으로 **분기(라우팅)**하고 진행을 관리한다.
**최소한의 코드로 요청 범위만** 구현한다 — 추측성 코드·요청 안 한 유연성은 넣지 않는다.

## When to Activate

- SDD 워크플로우의 **Implement 단계** — `task.md`가 준비되어 구현을 시작할 때
- `/workflow`가 task.md 단계의 작업으로 라우팅할 때

## Input

- 진행 체크리스트 (`task.md`). 없으면 `.tracking/{슬러그}/task.md`.
- 문제 분석 (`understand.md`) — 작업 모듈·레이어·제약
- 요구사항 (`request.md`) — 완료조건(AC)

## Procedure

### 1. 컨텍스트 적재

`task.md`의 작업 단계·완료기준, understand의 작업 모듈·제약, request의 완료조건을 읽는다.
이미 `- [x]`인 단계는 건너뛴다 (resume 지원).

### 2. 단계별 라우팅 (명시적 스킬 체이닝)

작업 단계를 **순서대로** 하나씩 진행한다. 각 단계의 성격을 판단해 알맞은 방법으로 구현한다.

| 작업 성격 | 방법 | 판단 기준 |
|---|---|---|
| 테스트 가능한 로직 | **`Skill(tdd)`** | Reducer·ViewModel·Service·Domain·순수 함수 |
| 화면/뷰 (SwiftUI) | **`Skill(swiftui-pro)`** + `docs/agent/swiftui-patterns.md`·`tca-patterns.md` 참고 | View·레이아웃·상태흐름·애니메이션 |
| 구조·아키텍처 | 직접 구현 (호출 없음) | 모듈 셋업·DI(WeaveDI) 배선·TCAFlow Coordinator·스캐폴딩 |

- 테스트 가능한 로직 단계 → `tdd` 스킬을 호출하고 그 절차(Red→Green→Refactor + 체크포인트 커밋)를 따른다.
- 화면 단계 → `swiftui-pro` 스킬 지침과 `docs/agent/`의 SwiftUI/TCA 패턴 가이드를 따른다.
- 구조·아키텍처 단계 → 별도 스킬 없이 직접 구현하되 기존 코드 스타일을 따르고 빌드로 확인한다.

레이어는 `understand.md`의 작업 모듈과 대상 레포 구조(README/AGENTS.md)로 판단한다.
한 단계가 두 성격을 걸치면(예: 화면 + 그 Reducer) 쪼개서 각각 맞는 방법으로 처리한다.

### 3. 실시간 체크 (핵심 책임)

**한 단계가 검증되면 즉시** `task.md`의 해당 항목을 `- [ ]` → `- [x]`로 바꾼다.
마지막에 몰아서 하지 않는다 — 도중 중단돼도 `/workflow`가 정확히 이어받게 하려면
진행 상태가 실시간으로 파일에 반영돼야 한다.

> 하위 스킬(`tdd` 등)에 위임하더라도 task.md 쓰기는 **이 오케스트레이터가** 한다.
> 진행 기록은 한 곳에서 관리해 충돌·누락을 막는다. 하위 스킬의 완료를 확인하고 체크한다.

### 4. 품질 게이트 대응

코드 편집 시 PostToolUse 품질 게이트가 위반을 잡으면 편집이 차단된다. 무시·우회하지 말고
**보고된 위반(파일·라인·수정 지시)을 고쳐 다시 적용**해 통과시킨다. 수정 후 재편집하면 1번
단계부터 재검증된다. (이는 구현 결함이므로 그 자리에서 고친다 — 계획 모순일 때만 5번대로 복귀.)

### 5. 계획이 틀렸다면

구현 중 계획(task)·분석(understand)의 오류나 모순을 발견하면 **임의로 우회하지 않는다.**
멈추고 사용자에게 보고한다 — plan(또는 understand) 단계로 되돌아갈 일이다.
(단, 품질 게이트 위반은 계획 문제가 아니라 구현 결함이므로 4번대로 고쳐서 통과시킨다.)

## Done

- `task.md`의 모든 작업 단계가 `- [x]`
- 완료 기준(DoD)이 충족됨
- (테스트로 구현한 부분은) 관련 테스트가 GREEN

내 변경으로 더 이상 쓰이지 않게 된 import·변수·함수는 제거한다.
완료 후 변경 요약과 남은 우려(있으면)를 사용자에게 보여준다.
