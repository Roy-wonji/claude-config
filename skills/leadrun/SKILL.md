# leadrun

리드(메인 대화) 하나와 도우미(`lead-helper`) 여럿으로 큰 작업을 끝낸다.
리드는 나누고·띄우고·상태를 맞추고·묻는다. **코드는 리드가 직접 고치지 않는다.**

출처: REBORN LABS leadagent(MIT)의 구조를 가져왔다. 원본은 도우미를 동시에 띄우지만,
이 하네스는 순차 실행 규칙을 따르므로 **도우미를 한 번에 하나씩** 띄운다.

## 1. 준비 확인

- git 저장소인지, 커밋 안 된 변경이 있는지 `git status --short --branch`로 본다.
  변경이 있으면 멈추고 사용자에게 어떻게 할지 묻는다.
- 저장소 `CLAUDE.md`에서 PR 대상 브랜치, 이슈 규칙, 검증 명령을 읽어 둔다.

## 2. 일 나누기

- 서로 **같은 파일을 고치지 않는** 할 일 3~5개로 나눈다. 순서 의존이 있으면 순서를 적는다.
- 할 일마다 목표 한 문장, 완료 기준, 고쳐도 되는 파일 목록을 정한다.
- **TASKS.md에 적기 전에 나눔을 사용자에게 보여 주고 허락받는다.**
- 저장소 규칙이 할 일마다 이슈를 요구하면, 허락받은 뒤 이슈를 만든다.

## 3. TASKS.md

위치: `.omc/leadrun/TASKS.md` (추적되지 않는 작업 파일). **리드만 고친다.**

```markdown
# <큰 작업 제목>

| ID  | 할 일 | 고칠 파일 | 이슈 | 브랜치      | 상태 |
| --- | ----- | --------- | ---- | ----------- | ---- |
| T1  | ...   | ...       | #N   | feature/... | 대기 |
```

상태값은 `대기 · 하는 중 · 끝남 · 막힘` 네 가지뿐이다. **도우미가 실제로 보고한 것만** 적는다.

## 4. 도우미 띄우기 (한 번에 하나)

- 다음 `대기` 할 일 하나를 `하는 중`으로 바꾸고 `lead-helper`를 띄운다
  (`Agent` 도구, `subagent_type: lead-helper`, `isolation: worktree`).
- 프롬프트에 할 일 ID, 목표, 완료 기준, 고칠 파일, 기준 브랜치, 브랜치 이름, 이슈 번호, 검증 명령을 모두 넣는다.
- 도우미가 돌아오면 보고대로 TASKS.md를 고친 뒤 다음 할 일로 넘어간다.
- `막힘`이면 다음으로 넘어가지 말고 이유를 사용자에게 보고한다.

## 5. 허락 받고 합치기

- 끝난 브랜치와 바뀐 파일을 보여 주고 허락받은 뒤 하나씩 푸시·PR·머지한다(저장소 git 규칙대로).
- 충돌이 나면 멈추고 알린다. 리드가 임의로 풀지 않는다.
- 바뀐 것이 없는 워크트리는 자동으로 지워진다. 남은 워크트리는 머지 후 정리한다.

## 규칙

- 나누기 전과 합치기 전에 반드시 묻는다.
- 같은 단계가 2번 실패하면 멈추고 보고한다. 허락 없이 세 번째 시도를 하지 않는다.
- 도우미가 권한을 물으면 멈춘다. 미리 허락할 명령은 사용자가 `/permissions`에서 정하고, 스킬이 대신 바꾸지 않는다.
- 리드와 도우미 모두 MCP는 `code-mode` 스킬로 처리한다(짧은 1회 호출·대화 전용 커넥터만 직접).
- 도우미 수만큼 사용량이 늘어난다. 2단계 이하 작업은 leadrun 없이 직접 처리한다.
