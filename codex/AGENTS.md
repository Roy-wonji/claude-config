# Codex 전역 지침

- 모든 답변은 한국어로 쓴다. 코드 · 식별자 · 명령어만 원문을 유지한다.
- 저장소의 `AGENTS.md` · `CLAUDE.md` · `.claude/docs`가 이 파일보다 우선한다.

## 코드 리뷰 (멀티 에이전트)

리뷰 · 점검 · PR 검토를 맡으면 아래 순서를 따른다. 파일을 고치지 않는다.

1. 기준 문서를 먼저 읽는다: 저장소 루트 `REVIEW.md`(있으면), `AGENTS.md`, `CLAUDE.md`, 바뀐 경로의 규칙 문서.
2. 리뷰 대상(diff · PR · 경로)이 작지 않으면 `security_reviewer` · `performance_reviewer` · `architecture_reviewer` 서브에이전트를 **병렬로** 띄운다. 정확성(버그 · 엣지 케이스)은 메인 세션이 직접 본다. 작은 변경(파일 1~2개)은 메인 세션 혼자 본다.
3. 결과를 모아 중복을 합치고 심각도(high · medium · low)로 정렬한다. 서로 부딪히는 의견(예: 보안 vs 성능, 가독성 vs 최적화)은 "가독성 우선안"과 "성능 우선안"처럼 두 안을 나란히 적고, 이 저장소 상황에 맞는 쪽을 근거와 함께 고른다.
4. 모든 지적에는 `파일:줄` 근거를 붙인다. 이름만 보고 추정한 동작은 지적하지 않는다.
5. 실행하지 못한 검증은 숨기지 않고 한계로 적는다. 지적이 없다는 것이 결함이 없다는 뜻은 아니다.

## 공통 프로젝트 하네스 (Claude · Codex)

- 모든 프로젝트의 작업 시작 시 cwd와 git 상태를 확인하고 `AGENTS.md`, `CLAUDE.md`를 읽는다. `CLAUDE.md`가 안내하는 `.claude/docs/` 문서 중 작업에 필요한 것만 읽는다. 경로별 `.claude/rules/`의 frontmatter를 확인하고 변경 경로에 맞는 규칙을 직접 읽는다. 이 디렉터리들이 없으면 해당 저장소의 README·기여 가이드·빌드 설정을 따른다.
- 저장소의 규칙 원본을 유지한다. `AGENTS.md`는 원본으로 연결하는 진입점이며 프로젝트 규칙을 다른 파일에 복제하지 않는다. 특정 프로젝트의 플랫폼·브랜치·이슈·커밋 규칙을 모든 프로젝트에 일괄 적용하지 않는다.
- 전역 roy-config는 공통 작업 방식만 정의한다. 기존 OMC·OMX 지침, 사용자 설정, 에이전트, 훅을 통째로 덮어쓰거나 중복 설치하지 않는다. 프로젝트별 권한 경계를 존중한다.
- 작업 순서는 이해 → 필요한 범위 구현 → 검증 → 독립 리뷰 → 근거와 결과 보고다. 명확하고 되돌릴 수 있는 승인된 작업은 계속 진행한다. 기존 사용자 변경을 보존하고 관련 없는 리팩터링·설정 변경을 섞지 않는다.
- Codex에는 Claude의 `.claude/settings.json` 훅이 자동 적용되지 않는다. 저장소가 요구하는 검증 스크립트와 git 규칙 검사를 직접 수행한다. `.claude/scripts/verify`가 있으면 사용법과 대상 경로를 먼저 확인하고 사용하며, 없으면 저장소의 lint·typecheck·test 명령을 선택한다. 소스 변경 없는 문서 작업에는 불필요한 전체 빌드를 실행하지 않는다.
- 검증 결과는 실제 실행한 명령·종료 코드와 한계를 보고한다. 훅 이벤트를 흉내 내어 Claude 스크립트를 Codex 훅에 무조건 등록하지 않는다. 기존 재시도·비용·승인 제한을 유지한다.
- 로컬 프로젝트 규칙을 먼저 적용하고 전역 기본값은 빈 곳만 보완한다. 기능 변경을 끝낼 때에는 아래 병렬 리뷰 계약에 따라 독립 검토를 사용한다. 단순 질의·오타 수정은 규모에 맞게 줄인다.

## 병렬 리뷰 실행 계약

- 코드 리뷰·PR 검토와 의미 있는 코드 변경 후 최종 검토에 적용한다. 이 절은 오래된 리뷰 팀 구성·순차 실행 지침보다 우선한다.
- 메인은 정확성·회귀·엣지 케이스를 검토한다. 독립 검토가 유용하면 보안·성능·아키텍처 3개 역할을 실제 서브에이전트로 병렬 실행한다. 작은 변경도 인증·동시성·저장소 경계를 건드리면 해당 역할을 포함한다.
- Claude 역할: `security-reviewer`, `performance-reviewer`, `architecture-reviewer`. Codex 역할: `security_reviewer`, `performance_reviewer`, `architecture_reviewer`. 해당 이름을 사용할 수 없으면 제공되는 범용 서브에이전트에 같은 역할을 명시한다. 동시 실행 한도에 맞춰 묶어서 실행한다.
- 각 리뷰어에 동일한 기준 커밋·diff·대상 경로 및 검증 결과를 전달한다. 미커밋 변경과 untracked 파일의 포함 여부를 명시하고, 리뷰 중 변경되면 영향을 받은 부분을 다시 확인한다.
- 저장소의 `AGENTS.md`, `CLAUDE.md`, `REVIEW.md`(있으면), 경로별 규칙을 먼저 읽는다. 로컬 내장 `/code-review`는 `REVIEW.md`를 자동으로 읽지 않으므로 핵심 규칙은 `CLAUDE.md`에도 연결한다.
- 리뷰어는 제품 코드·설정을 수정하거나 추가 에이전트·교차 CLI를 재귀 호출하지 않는다. 작업 결과는 메인에 반환한다. Claude 리뷰어는 읽기 도구만 사용하며 diff·테스트 결과는 메인이 제공한다. Codex의 읽기 전용 지침은 권한 격리가 아니며 부모의 샌드박스·승인 정책을 그대로 따른다.
- 먼저 독립 의견을 수집한 뒤 메인이 중복을 합치고 실제 코드·반례로 재검증한다. 다수결이나 여러 에이전트의 동의만으로 신뢰도를 올리지 않는다.
- 발견사항은 심각도(high/medium/low), 파일:줄, 재현 조건, 영향, 수정 방향, 관련 규칙을 포함한다. 취향·추측은 결함과 분리하고 실행하지 않은 테스트·누락한 영역을 명시한다. 충돌하는 의견은 가독성·성능·보안의 실제 트레이드오프를 비교해 선택한다.
- 단일 대화의 역할극은 독립 에이전트 리뷰로 보고하지 않는다. 도구나 용량이 없으면 단일 리뷰로 진행하고 한계를 알린다. 리뷰 결과만으로 자동 승인·머지·댓글 게시하지 않는다.
- 내장 `/code-review`는 대안으로 사용하며 전문 리뷰와 매번 중복 실행하지 않는다. `/code-review ultra`(`/ultrareview`)는 클라우드 업로드와 별도 실행 확인이 필요한 명시적 경로다. GitHub 관리형 리뷰는 조직·GitHub 앱 연결이 필요하며 로컬 설정만으로 활성화되지 않는다.
